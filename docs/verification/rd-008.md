# RD-008 다중 Renderer와 장시간 실행 검증 결과

실제 Electron에서 두 창의 세션·권한·업스트림 공유, 느린 소비자 격리, overflow, 동시 RPC, reload, 반복 구독·해제를 검증한 결과다. 단위·타입 검사와 실제 Electron 실행 결과를 구분해 적는다.

## 검증 환경

| 항목        | 값                                                                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 플랫폼      | Linux 6.17.0-40-generic x86_64, Ubuntu 24.04.4 LTS                                                                                   |
| 디스플레이  | `xvfb-run -a`(가상 X 서버), 창은 `show: false`                                                                                       |
| 런타임      | Electron 44.4.5, Node v24.21.0, pnpm 11.25.0                                                                                         |
| 테스트 도구 | vitest 5.0.1, `@playwright/test` 1.63.0(`_electron.launch`)                                                                          |
| 빌드 형태   | 패키징하지 않은 개발 빌드. 라이브러리는 `tsup` 산출물(`dist/`, ESM), fixture는 `tsup`으로 main(esm)·preload(cjs)·renderer(iife) 번들 |
| Renderer    | `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `file://` origin                                                |

fixture의 main·preload는 패키지 self-reference로 `dist/`를 쓰고 renderer는 `src/`를 번들한다. turbo `@cp949/rx-bridge-electron#test`는 `build`에 의존하므로 `pnpm test`/`pnpm verify`는 최신 `dist/`로 실행된다.

## 실제 Electron 기능 시나리오

`packages/rx-bridge-electron/test/electron/multi-window/multi-window.electron.test.ts`. 창 두 개(`editor`, `viewer`)를 같은 서버에 attach한다. `authorize`는 viewer의 `rpc:lab/secure`·`rpc:lab/hold`를 거부한다. Main 관측은 테스트 전용 probe(진단 스냅샷, `DiagnosticsSink` 기록, upstream subscribe/unsubscribe 카운터)로 한다. 기본 `pnpm test`와 CI에 포함된다. 연속 10회 실행 모두 7/7 통과.

| 시나리오                             | 테스트                                                                         | 결과                                                                                                                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 창별 세션 분리                       | gives each attached window its own session                                     | 통과. `sessions`=2, `session-opened` 2건                                                                                                                                                    |
| 창별 권한 격리                       | denies role-restricted RPC only in the viewer window                           | 통과. 같은 RPC가 editor 성공·viewer `FORBIDDEN`, `rejected/authorize-denied` 1건(key만 기록), viewer의 허용 RPC·State 구독 정상                                                             |
| 업스트림 공유                        | shares one upstream subscription across windows until the last consumer leaves | 통과. 두 창 State·broadcast Event 구독에 upstream subscribe 각 1회, 한 창 해제 후 유지, 마지막 해제 후 unsubscribe 1회                                                                      |
| 느린 소비자 + `error` overflow       | ends only the slow consumer's subscription on error overflow                   | 통과. ack를 보내지 않는 viewer 구독만 overflow. editor 10/10 수신, viewer의 다른 State 구독 정상. 종료 통지는 대기 값을 ack 순서대로 전달한 뒤 `STREAM_OVERFLOW`로 도착하고 그 뒤 슬롯 반환 |
| 느린 소비자 + `drop-oldest` overflow | keeps the slow consumer subscribed and records drops on drop-oldest overflow   | 통과. editor 10/10, `stream-dropped` count 합 5, viewer 구독 유지 후 ack 재개 시 최신 4개 수신                                                                                              |
| 동시 RPC 세션 격리                   | isolates a session at its RPC limit from the other window                      | 통과. editor 64건 진행 중 65번째 `RESOURCE_EXHAUSTED`(`rejected/rpc-limit` 1건), 같은 시점 viewer RPC 성공, 해제 후 `rpcInFlight`=0                                                         |
| reload 정리                          | cleans up the reloaded window's session while the other window keeps streaming | 통과. editor reload 시 진행 중 RPC 3건 `rpc-cancelled`, 구독 2건 closed, upstream 유지, viewer 계속 수신, 새 editor 세션 RPC 성공                                                           |

sender 검증(attach하지 않은 창 `FORBIDDEN`, 자식 iframe 미노출, `data:` origin 거부)은 기존 `test/electron/bridge.electron.test.ts`의 "rejects child frames, unattached windows, and disallowed origins after a reload"가 같은 환경에서 통과한다.

## 반복 실행(soak)

`packages/rx-bridge-electron/test/electron/multi-window/multi-window.soak.ts`. 기본 테스트와 CI에서 제외하고 `xvfb-run -a pnpm --filter @cp949/rx-bridge-electron test:soak`로 수동 실행한다. 판정은 시간이 아니라 반복 후 Main 자원이 기준선으로 돌아오는지다.

| 단계      | 반복                                         | 소요   |
| --------- | -------------------------------------------- | ------ |
| 구독/해제 | 창별 1000회(State + Event)                   | 482ms  |
| reload    | editor 50회, 매회 구독 2개와 진행 중 RPC 2건 | 2495ms |
| 동시 RPC  | 64건 × 20라운드, 라운드마다 다른 창 RPC 확인 | 235ms  |

종료 시 결과:

- 스냅샷 `{ sessions: 2, rpcInFlight: 0, subscriptions: 0, queuedEvents: 0 }`
- upstream subscribe/unsubscribe: status 1643/1643, notice 1615/1615
- 진단: `session-opened` 52 / `session-closed` 50(활성 2), `subscription-opened` 4101 / `subscription-closed` 4101, `rpc-cancelled` 100, `rpc-finished` 1400(취소된 RPC도 handler 종료 시 기록)

## 미검증

- Windows, macOS
- 패키징 빌드(electron-builder 산출물). `apps/demo`의 Linux packaged 실행은 CI가 별도로 검사하지만 이 시나리오 집합은 아니다
- Electron 44.4.5 외 버전(peer 범위 `>=29`)
- `drop-newest` 정책의 실제 Electron 경로(단위 테스트만). drop 정책 간 차이는 `BoundedQueue.push` 분기뿐이다
- Renderer 쪽 종료 통지(reload·retire 시 Renderer에 terminal을 보내지 않음. `.scratch/shutdown-renderer-notify`)
- 힙·메모리 누수와 시간 기반 장시간 실행

## 발견과 처리

- `error` overflow의 종료 통지는 대기 값 전달 뒤에 온다. ack를 보내지 않는 소비자는 retire·unsubscribe 전까지 구독 슬롯과 capacity만큼의 대기 값을 점유한다. 설계된 동작이다(단위 테스트가 순서를 고정). 다만 "overflow 뒤 슬롯 즉시 반환"으로 읽히는 문서 문구와 어긋나 [`.scratch/overflow-slot-timing`](../../.scratch/overflow-slot-timing/issues/01-overflow-terminal-after-drain.md)으로 등록했다.
- Playwright에서 창 URL을 확인한 직후 Renderer 번들 전역을 읽으면 스크립트 실행 전이라 간헐 실패한다. multi-window 하니스는 전역 준비를 기다린다. [TRP-003](../traps/TRP-003-electron-renderer-global-race.md)으로 등록하고 [TRP-001](../traps/TRP-001-demo-electron-e2e-flake.md)에 같은 계열 가설로 연결했다.
- 라이브러리 코드 결함은 발견하지 않았다.
